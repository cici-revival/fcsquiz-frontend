## 🔴 `/v1/signs/stream` недостижим из браузера (401)

**Где:** `services/gateway/internal/api/rest/server/server.go:56`,
`internal/api/rest/middleware/auth.go`

**Проблема:** роут стоит на `authChain`, а middleware читает **только**
заголовок `Authorization: Bearer` (`auth.go:45`). Браузерный `EventSource`
заголовки задавать не умеет — `withCredentials: true` шлёт лишь куки, которые
middleware не смотрит. Значит эндпоинт из браузера недостижим в принципе:
подключение всегда 401.

Проверено curl'ом по staging: без заголовка — 401, с мусорным Bearer — 401,
публичный `/v1/game/state` при этом держит соединение.

**Нужно** одно из двух:

- принимать одноразовый тикет в query, как уже сделано для рассадки:
  `POST /v1/adminka/ws-ticket` → `?ticket=...`, `tickets.Consume`
  (`seating_websocket.go:53-60`). Фронт умеет это делать — `issueWebSocketTicket`
  уже есть в `adminkaApi`;
- либо перевести роут на `publicChain`, если подписи не секретные.

**Почему важно:** страница «Таблички» не получает обновления вообще. Фронт
бесконечно переподключается с бэкоффом, дёргая `tryRestoreSession()` перед
каждой попыткой — но обновление токена тут не помогает, его всё равно нечем
передать. Пользователю при этом ничего не видно.

## 🔴 Heartbeat в SSE

**Где:** `services/streams/internal/api/rest/handler/` — `game_state.go`, `sse_handler.go`

**Проблема:** сервер пишет в сокет только когда есть события. В затишье между
регистрациями соединение молчит, и прокси рвёт его по таймауту простоя
(обычно 60 с). Для клиента это выглядит как обрыв на ровном месте.

**Нужно:** слать `: keepalive\n\n` каждые 15–30 секунд.

**Почему важно:** затрагивает публичный лендинг. Фронт переподключается
с экспоненциальным бэкоффом, но это лечит симптом, а не причину.

## 🔴 Публичный снимок состава (nice to have)

**Проблема:** лендинг получает данные только через SSE. Обычного GET нет:
`/v1/game/registered_teams` под `bearerAuth` и требует обязательные
`season` + `game_number`, а лендинг узнаёт номер игры из самого SSE.

**Нужно:** `GET /v1/game/current_roster` — без авторизации, без параметров,
отдаёт состав текущей игры.

**Даст:** лендинг сможет показать данные сразу и кэшировать их на CDN,
а SSE подключать только для живых обновлений. Снимет постоянные соединения
от посетителей, которые просто зашли посмотреть.

**Приоритет:** ниже heartbeat. Делать по факту нагрузки, не заранее.

## 🔴 Роль admin для yapet1711@yandex.ru (staging)

**Где:** `services/users/internal/adapters/repository/users/postgres/login.go:66`

**Проблема:** в токене приходит `"role": "user"`, а `ProtectedRoute` требует
`admin`. Новый пользователь всегда создаётся с ролью `user` — она зашита
в INSERT. При повторном входе `ON CONFLICT` обновляет только email, роль
не трогает, поэтому перелогином её не изменить.

**Нужно:** выполнить на базе staging

```sql
UPDATE users.users
SET role_id = (SELECT id FROM users.roles WHERE name = 'admin')
WHERE email = 'yapet1711@yandex.ru';
```

После этого запросить новую magic-link: старый токен подписан со старой ролью.

**Блокирует:** проверку админки на staging.

**Попутно:** способа выдать роль через API нет — ни эндпоинта, ни CLI.
Если админов будет больше одного, понадобится команда или сид.
